# Risks and Technical Debts

| Nr  | Description                                                                                                                                                          | Severity (1 = very low, 5 = very high) | Probability (1 = very low, 5 = very high) | Mitigation strategy                                                                                                                    |
|-----|------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------|---------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------|
| R1  | GraalVM native image deployment is not working                                                                                                                        | 1                                        | 4                                            | Deploy as non-native-image (current state of all app modules; none of them build a native image today).                                 |
| R2  | Clockify's report API has no versioning contract known to this project. A breaking change on Clockify's side would silently break `importing` for all five app modules at once. | 3                                        | 2                                            | Keep the Clockify HTTP client behind a `domain.port` (see [AD3](09_architecture_decisions.md#ad3-ports--adapters-inside-importing-and-exporting)) so a breakage is isolated to one adapter; add an E2E scenario against recorded Clockify responses to catch shape drift early. |
| R3  | Five independent build/deploy stacks (CloudFormation/SAM, Bicep, Terraform, Scaleway CLI, plain jar) and three web frameworks (Micronaut, Quarkus, Spring Boot) each evolve on their own schedule. With a single maintainer (OC1), keeping all five current is a recurring cost. | 3                                        | 3                                            | Dependabot handles routine dependency bumps; `tw-core`/`tw-spi` isolation ([AD1](09_architecture_decisions.md#ad1-business-logic-decoupled-from-cloudframework-via-tw-core--tw-spi)) keeps the blast radius of any one stack's breakage local to its own app module. |
| R4  | The `importing`/`exporting` anticorruption boundary (AD2) is enforced only by `archTest`, which is not part of `:tw-core:test` — a developer running just the unit tests could merge a boundary violation locally before CI catches it. | 2                                        | 2                                            | `./gradlew check` (which includes `archTest`) is what CI runs on every push and what CLAUDE.md instructs before considering a task done; no separate enforcement needed as long as that convention holds. |
